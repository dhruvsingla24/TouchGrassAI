# TouchGrass AI 🌿
**Less scrolling. More noticing.** A local-first outdoor adventure coach that helps you take small, practical breaks in the world beyond your screen.

## What's implemented
- Responsive, nature-inspired UI and working routes: Home, Discover/Builder, Quest details, Screen-Free Adventure, completion/reflection, Adventure Library, Progress, Settings.
- Eight predefined demo quests across nature, movement, mindfulness, creativity, gardening, and observation. Every demo quest is labelled as not AI-generated.
- Optional Ollama `/api/generate` integration using a configurable local model; JSON output is parsed and validated with Zod. Ollama connection test uses a real `/api/tags` request.
- Local persistence using IndexedDB/Dexie for saved quests, completed adventures, and reflections. Preferences/provider settings use localStorage.
- Screen-free mode with pause/resume, step navigation, explicit finish, and browser speech synthesis for quest instructions.
- Voice mode preference, voice selection where supported, speaking-speed control, and a Terra speech test.
- Progress based on stored completed records; reflection journal, deletion, and clear-data action.
- Responsive layouts, visible focus states, semantic controls, and reduced-motion support.

## Requirements
- Node.js 20+ recommended
- npm
- Optional: [Ollama](https://ollama.com/download) and a compatible open-weight model

## Run locally
```bash
npm install
npm run dev
```
Open the local URL Vite prints (normally `http://localhost:5173`).

## Enable local AI with Ollama
1. Install and start Ollama: https://ollama.com/download
2. In Terminal, pull a model that your machine can run, e.g.:
   ```bash
   ollama pull llama3.2
   ```
3. Open TouchGrass AI → Settings → Open-weight AI → Local Ollama.
4. Confirm base URL (default `http://localhost:11434`) and model name (`llama3.2`).
5. Click **Test connection**. This requests `/api/tags`; success means the server returned its installed model list, not that every model works with generation.
6. Try generating a quest. The app sends the selected preferences to the configured Ollama endpoint and validates the returned JSON.

### CORS / local proxy note
A browser may block requests to Ollama because of CORS/origin settings. This prototype does not silently claim that Ollama is connected. If direct browser access is blocked, configure Ollama's permitted origins for your local development environment or add a local server-side proxy. Do not place hosted-provider secrets in frontend code.

## AI provenance
- **Demo mode:** a predefined local quest, clearly labelled `Demo quest · Not generated by AI`.
- **Local Ollama:** only labelled as locally generated when the request returns valid, schema-checked JSON.
- **Connection status:** Settings tests `/api/tags`; the header says local AI is unverified until you test it. A successful connection test does not guarantee that generation will succeed.
- This prototype does not include a hosted inference provider or a remote AI fallback.

## Privacy
- No account, GPS, camera, or analytics are required.
- Saved quests, activity records, and reflections are stored in browser IndexedDB.
- Provider and voice preferences are stored in localStorage.
- Quest prompts/preferences are sent to your configured Ollama endpoint when you generate with local AI. Reflections are not included in prompts.
- Browser speech synthesis uses platform/browser voices; it is separate from open-weight AI. Browser speech recognition is not implemented.

## Offline and PWA limitations
A manifest is included, but service-worker caching, full installable PWA behavior, and offline app-shell support are **not yet implemented**. IndexedDB data remains local, but a fresh page load may require the development server/network. AI generation is not claimed to work offline.

## Timer note
The active screen calculates elapsed time from timestamps and excludes pauses during the current session. The current prototype does not persist active adventure state across refreshes; do not treat it as a production-grade background timer.

## Tests and build

## Safety
Activities are optional and should be adapted to the user's environment and ability. Avoid restricted areas, roads, wildlife contact, and touching or eating unknown plants. Postpone outdoor activity when conditions feel unsafe.
